# LM-21 · B7-4: API de lectura y exportación del modelo

**Lote del modelo** · REQ-MOD-6 (B7-4, ADR-006 §6 fila 4) · **Estado: registrado** (borrador; entra después de LM-20 aceptado) · **Categoría: normal** (solo lectura; el token `tablero` lo pone Carlos en B7-5) · Redacta: Arquitecto · Construye: CLI · Acepta: juez local · Reversión: `git revert`.

## Qué entrega (en `str-manager/modelo/api/`)
- `GET /modelo/api/<entidad>` y `/<entidad>/<id>` para las 14 tablas, con filtros `estado`, `since` (`server_time` en ms, lección DT-20) y `proyecto` (por defecto `str`). Mientras no exista la tabla `credencial` (B7-5), exige el token del Arquitecto; después, cualquier rol con lectura.
- `GET /modelo/api/estado`: lo que hoy es `buzon\estado-vivo.json` (cola, verificando, métricas de `cambio.tiempos`).
- `GET /modelo/api/export`: devuelve `seguimiento.json`, `diseno.json` y `mensajes.json` **con la forma de hoy** (sale de las filas + `extra`).

## Espejo en Git
La cola (v7.3) pide `export` una vez al día y a pedido (`modelo-cargas\EXPORTAR`), y deja los tres archivos en `log\espejo\`; el Chat Desarrollo (o el Arquitecto) los sube a la rama `espejo` de `str-manager-docs` con su token. El servidor no guarda token de GitHub.

## Pruebas de aceptación
- a. `tests/modelo-lectura.test.js`: rutas, filtros y forma (N1).
- b. Ida y vuelta: carga de LM-20 → `export` → `validar.py` sobre lo exportado = 0 errores (N2 por la cola).
- c. Igualdad: `export` reproduce los JSON del commit cargado, iguales salvo el orden de claves (N2; compara con `json.loads` ordenado).
- d. Sin token → 401; `proyecto=prueba` nunca aparece en `export` (N1 + N2).

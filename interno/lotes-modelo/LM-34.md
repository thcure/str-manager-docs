## Por qué
Hoy cargo el servicio a mano por la cola. Para que las páginas lean del servicio (B8) tiene que estar al día y validado también con LENOVO apagado. Git sigue siendo el registro oficial; el servicio es la copia validada de la que se lee (plan v2 §3).

## Quién más depende
Seg. Proyecto (B8) leerá `sha` y `cargadoEn`; el Panel STR (fila `fabrica.`); la carga manual por la cola (`modelo-cargas\paquete-*`), que desde la aceptación solo se usa con el flujo apagado, para que un sha viejo no pise uno nuevo (ajuste de Desarrollo).

## Qué entrega
1. **`modelo-sync.yml`**: disparo solo `push` a `main` con cambios en `interno/**` o `herramientas/modelo/**`, y manual (`workflow_dispatch`); **nunca `pull_request`** (ajuste de Diseño). `concurrency: modelo-sync` **sin** `cancel-in-progress`: la carga en curso termina y de las pendientes queda la última (ajuste de Desarrollo). Pasos: checkout → `validar.py` → si «Errores» ≠ 0, rojo; el resumen lista **archivo y regla** de cada error y el registro dice «cargar: no llamado (validación en rojo)» → `paquete.py --complemento --sha $GITHUB_SHA` → `POST cargar` con `X-Modelo-Token: ${{ secrets.MODELO_TOKEN }}` (rol `carga`) → `GET salud` con `db:true` y el `sha` cargado.
2. **`modelo-espejo.yml`**: diario (06:10 Bogotá) y manual: `GET export` y compara cada archivo con `git show <sha cargado>:<ruta>` byte a byte; diferencia = rojo con la lista de rutas, sin contenido.
3. **`sync.py`** (biblioteca estándar de Python) y **`sync_test.py`** con servidor falso local (200, 401, 403, 422, 500, tiempo agotado). Registro: solo sha corto, códigos, conteos por tabla y duración; nunca el token, nombres de REQ ni textos.
4. **`paquete.py --sha`**: el paquete ya lleva `sha`; la opción permite pasar el de GitHub. El servicio lo guarda y `salud` devuelve `{sha, cargadoEn}` (parte del lote «rol carga», M-345).
5. **Panel v4.6**: fila `fabrica.` = «sincronizado HH:MM (sha)»; en ámbar «validación en rojo» o «sincronización fallida» (Hostinger), según el paso que falló. Consulta la API pública de GitHub cada **10 min con ETag** (`If-None-Match`; el 304 no gasta cupo), para no competir con los guiones de la zona «proyecto».
6. README del modelo y ficha **BAI10-m** en `interno/conocimiento.json`: cómo funciona, cómo se apaga, cómo se rota el token, «nunca `pull_request`» y «carga manual solo con el flujo apagado».

## Qué entrega
1. `.github/workflows/modelo-sync.yml` en `str-manager-docs`:
   - **Disparo:** `push` a `main` con cambios en `interno/**` o `herramientas/modelo/**`; también manual (`workflow_dispatch`). `concurrency: modelo-sync` (uno a la vez; si llegan dos, corre el último).
   - **Pasos:** checkout del commit → `python3 herramientas/modelo/validar.py` (si «Errores» ≠ 0, termina en rojo sin cargar) → `paquete.py --complemento --salida paquete.json` → `POST /modelo/api/cargar` con la cabecera `X-Modelo-Token: ${{ secrets.MODELO_TOKEN }}` → `GET /modelo/api/salud` y comprueba `db:true`.
   - **Registro:** solo sha corto, código HTTP, conteos por tabla y duración. Nunca el token, el paquete ni la respuesta completa.
2. `.github/workflows/modelo-espejo.yml`: una vez al día (06:10 Bogotá) y manual: `GET /modelo/api/export` y compara cada archivo con `git show <sha cargado>:<ruta>` byte a byte. Una diferencia = rojo, con la lista de rutas (sin contenido).
3. `herramientas/modelo/sync.py`: lo que llaman los dos flujos (cargar, comprobar, exportar y comparar), solo con la biblioteca estándar de Python; prueba `herramientas/modelo/sync_test.py` con un servidor falso local (200, 401, 422, 500 y tiempo agotado).
4. Panel STR v4.6: la fila `fabrica.` dice «sincronizado HH:MM (sha)» o se pone en ámbar con «sincronización fallida», leyendo el último resultado de los dos flujos en la API pública de GitHub (sin token; una consulta cada 5 min).
5. `herramientas/modelo/README.md` y la ficha BAI10-m: cómo funciona, cómo se apaga y cómo se rota el token.

## Riesgos
| Riesgo | Mitigación |
|---|---|
| Token en GitHub | Secreto enmascarado; nunca en registros; rotación con `CREDENCIALES`; deuda: rol «carga» solo para cargar y exportar |
| Carga mala | El servicio se rehace desde Git (idempotente); la vuelta atrás no borra nada |
| Muchos `push` | `concurrency`; cada carga reemplaza todo `proyecto='str'` (como hoy) |
| Hostinger rechaza a GitHub | Prueba a primero; plan A como respaldo |
